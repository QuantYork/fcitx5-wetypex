# Linux 微信表情

微信的 `[微笑]`、`[捂脸]` 等内置表情使用专属图片和文本别名。将它们替换为外观接近的 Unicode emoji，会改变含义和外观。本实现使用原版微信输入法 2.2.3.657 安装包中的图片，候选窗口显示原图，向应用提交 Linux 微信支持的文本别名。

## 资源与显示

运行正常的原版资源安装流程即可安装表情。已有运行时可仅更新界面资源：

```bash
fcitx5-wetypex-setup --archive /path/to/WeType_2.2.3_657.zip --icons-only
```

安装器沿用原版压缩包 SHA-256 校验，将 PNG 提取到 `$XDG_DATA_HOME/fcitx5-wetypex/ui/wechat-emoticons/`，并在 `$XDG_DATA_HOME/fonts/fcitx5-wetypex-wechat.ttf` 生成彩色字体。未设置 XDG 变量时使用 `~/.local/share`。生成需要 fontTools、Pillow 和 fontconfig，发行包已声明这些依赖。源码环境缺少 fontTools 或 Pillow 时，安装器给出提示，候选仍显示文本名称。

Fcitx 的候选文本接口没有图片字段。因此本地字体仅把内部私用码位 `U+10F000–U+10F0FF` 映射到原图，让现有 Classic UI 或支持相同字体的候选界面绘制图片，无需另开抢焦点的窗口。私用字符只用于候选显示，提交使用引擎候选 ID 和文本。图片旁保留名称；字体未就绪时显示名称，不使用相近的 Unicode emoji 代替。

安装后重启 Fcitx5，让候选界面加载新字体。若使用独立的桌面候选面板且仍未加载新字体，也需要重新启动该面板。

原图和派生字体只保存在用户数据中，不进入源码包、发行包或仓库。仓库中的 `data/wechat-emoticons.json` 只保存别名、图片文件名和显示码位等功能映射。

## 微信应用范围

插件使用 Fcitx 输入上下文提供的程序标识，精确识别 `wechat`、`weixin`、`xwechat`、`com.tencent.WeChat` 和 `com.tencent.Weixin`，忽略大小写和 `.desktop` 后缀。WeChatAppEx 浏览器、网页微信、其他应用和无法识别的上下文均不启用微信表情。普通 Unicode emoji、颜文字等原有开关保持独立。

部分原生 Wayland 输入协议只暴露共享上下文，不提供程序身份。这种情况下关闭微信专属候选，不根据窗口标题或“上一个窗口”推测应用。通过客户端输入法接口提供应用身份的微信会话可正常识别。密码输入仍沿用输入法的禁用规则。

后端在发布候选快照前过滤专属或不受支持的别名，保留原引擎的候选 ID，因此过滤后翻页、数字选词和云候选刷新仍使用正确 ID。

## Linux 客户端兼容依据

名称映射依据本机原生 Linux 微信 `4.1.13.26` 中的经典表情别名表，以及资源 `:/emoji/newemoji-config.xml`。与原版输入法的 PNG 对应后，确认 149 张图片、379 个受支持或可规范化的别名。以资源文件名为依据关联图片，不按 Unicode emoji 的相似外观推断图片。

旧表与新表重名时采用新表的名称和图片，例如 `[Blush]` 使用 `[囧]`，`[再见]` 使用 `smiley_39b.png`。原版包中保留的旧图片仍可生成字体字形，但不覆盖新表的别名映射。

提交时统一为客户端支持的中文别名。例如原版输入法的 `[折磨]` 对应相同的经典图片，但当前 Linux 微信名称为 `[疯了]`，因此使用后者；`[Bah!L]`、`[Bah!R]` 使用对应的中文名称。13 个未确认能被该 Linux 客户端识别的额外别名不作为表情候选发布。

这些别名的图形解析由微信客户端完成，输入法本身不会把文本转换为发送图片或贴纸的操作。微信后续版本若改变支持的名称，需要核对映射后更新。
